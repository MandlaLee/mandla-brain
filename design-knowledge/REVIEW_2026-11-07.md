# Audit of Mandla Design Knowledge Base — 7 November 2026

## Why a second pass was necessary
The original v1.0 contained 25 chapters with extensive guidance on identity, psychology, typography, layout, research, QA and design systems. A review against contemporary public AI design skills found a strong **knowledge base** but a weaker **repeatable implementation skill**. The biggest gap was between making recommendations and verifying the actual software or visuals. This audit records why v1.1 added six chapters, revised the skill, and added agent entrypoints.

## Sources directly inspected
- [Anthropic frontend-design SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md): grounding in subject matter, aesthetic plan, anti-default critique, copy and screenshot reflection.
- [Anthropic webapp-testing SKILL.md](https://github.com/anthropics/skills/blob/main/skills/webapp-testing/SKILL.md): browser interaction and rendered evidence.
- [Anthropic canvas-design SKILL.md](https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md): visual philosophy for static art; not universally applicable to app UX.
- [Vercel web-design-guidelines SKILL.md](https://github.com/vercel-labs/agent-skills/blob/main/skills/web-design-guidelines/SKILL.md) and [current rules](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md): detailed auditable web guidance and code finding format.
- [Vercel React best-practices SKILL.md](https://github.com/vercel-labs/agent-skills/blob/main/skills/react-best-practices/SKILL.md): stack-specific performance priorities.
- [Impeccable README](https://github.com/pbakaus/impeccable), [audit](https://github.com/pbakaus/impeccable/blob/main/skill/reference/audit.md), [hardening](https://github.com/pbakaus/impeccable/blob/main/skill/reference/harden.md): separate critique/audit, project context files and edge-case hardening; also third-party execution risks.

- [Agent Skills specification](https://agentskills.io/specification), [OpenAI Build Skills](https://learn.chatgpt.com/docs/build-skills), [Claude Skills](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) and [VS Code skills](https://code.visualstudio.com/docs/agent-customization/agent-skills): packaging, metadata and discovery.

## What this audit does **not** prove
- That the various third-party skills outperform Mandla Design Director in a controlled study.
- That any third-party skill is installed locally or enabled in any ChatGPT/Claude account.
- That all links on the wider internet will remain reachable or always use the same rules.
- That a newly generated app/webpage is good without actual screenshots, interaction tests and approval.
- That a repository rule universally overrides platform/system instructions or user-requested changes.

## Remaining worthwhile extensions
1. Build synthetic, non-sensitive **working fixtures** for Chapter 30 in a separate test repository, and run actual design-skill comparisons.
2. Add optional read-only screenshot-diff automation and browser tests to *each active product repo* rather than trying to execute web tests from this reference repo.
3. Create approved project-specific `PRODUCT.md` and `DESIGN.md` for Aurum and Phala Digital **after inspecting their current sources**.
4. Run targeted participant tests to validate discoverability, brand attribution and accessibility; record sample sizes honestly.
5. Periodically refresh evolving AI skills, platform UI guidelines, licences and tooling security.
6. Verify remote memory/Notion sync independently when required. A GitHub change is not proof that every downstream assistant has read it.

## Maintenance rule
When a new recurring AI-generated design defect appears, add a reproducible failure fixture and a tested prevention instruction rather than merely expanding adjective lists. Avoid increasing the handbook's length without increasing its usefulness. Keep the canonical skill compact enough to trigger reliably.
